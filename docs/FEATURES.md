Generated by `tools/gen_features.py` from the object model and the alert tables of the pack. Do not edit by hand. Version française : [FEATURES.fr.md](FEATURES.fr.md).

## Summary

- 16 object types, 164 metrics in 23 groups, 148 properties, 26 key indicators.
- 83 alert definitions, 144 symptoms, 50 recommendations. 17 alerts count against the Risk badge, the others against Health.
- 4 custom groups, 5 dashboards, 8 list views, 1 report, 1 inventory tree, an icon per object type.
- Read-only collection from NSX. Account settings, certificate trust, sizing and upgrade are in [OPERATIONS.md](OPERATIONS.md).

## What the collection does

- Finds the active Global Manager in every cycle and follows a switchover when the account lists both Global Managers.
- Discovers the Local Managers from the Global Manager and checks each certificate against the thumbprint the Global Manager holds, or (certificate trust ca) against a trusted CA and the address; every connection is bound to the certificate that was checked.
- Keys edge nodes and RTEP tunnels by NSX transport node ID and sync channels by site ID, so a rename keeps the object and its history.
- Keeps collecting the Local Managers when no Global Manager answers, from the location list of earlier cycles (adapter cache, then VCF Operations).
- Reports a failed NSX call as unknown data: nothing is sent for the values behind it, and the call is listed on the federation object.
- Works within a call budget per manager, backs off on HTTP 429 and 503, retries a timeout once and skips a manager that keeps timing out for the rest of the cycle.
- Computes rates from the NSX counters, and rollups for the whole federation.
- Reads the latency and the fill of the sync queues of each location from the flow details of the Global Manager, and compares the latency with the maximum RTT set in NSX.
- Computes the share of packets each RTEP tunnel drops, and the drop rate of the Tier-0 BGP sessions and of the inter-site BGP sessions.
- Reads the realization of every stretched object in every cycle up to 200 objects, and in a sweep of six cycles above that.
- Leaves the federation alarms of a Local Manager to the built-in NSX integration when that integration monitors it, and links its edge nodes and edge clusters to the built-in objects.
- Keeps the alerts of dependent objects quiet while a location is cut off from the Global Manager.
- Reads the CPU, memory and disk use of each federation edge node, and the HA state and routing of each stretched Tier-0 service router on it, from one call per edge. The status and threshold alerts of an edge stay quiet for an edge the built-in NSX integration monitors, as it raises the same NSX alarms.
- Tells when a stretched Tier-0 gateway has no active service router, in the federation or, for an active-active gateway, at one location, and when a service router changes HA state.
- Records changes between cycles: the active Global Manager, the role and version of each Global Manager, locations added, removed or upgraded, edge nodes added or removed, Tier-0 service router HA state, and stretched objects created, changed or deleted. Each change is an information event on its object and is listed on the federation.
- Compares the clock of every manager with the active Global Manager (from the system time NSX returns, corrected for the duration of the call) and reads the NTP servers and service of each.
- Reads the configuration limits of each Local Manager as NSX rates them, since global objects count at every location of their span, and lists the global objects overridden at a location.
- Tells whether a standby Global Manager can take over: ready, not ready with the reasons (sync with the active, cluster health, version, expired certificate, upgrade in progress or paused), or unknown when a value could not be read. The metric is 1 only when that is confirmed.
- Optionally deletes the objects that left NSX (off by default).
